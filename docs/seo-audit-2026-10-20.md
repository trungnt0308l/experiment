# SEO audit and implemented changes

## Summary

Live homepage, archive, robots.txt, and sitemap returned HTTP 200. The sitemap contained 615 URLs covering 554 published incidents, archive pages, and six other public pages. These numbers describe discovery, not Google index coverage or rankings. Search Console and traffic baselines were unavailable.

Applied `seo-audit`, `seo-title-optimization`, and `schema-markup`. The existing PRD defines security, risk, and compliance teams evaluating AI vulnerabilities and incident monitoring as the audience. Search results for AI security incident databases and prompt injection supported incident archives, advisory identifiers, source citations, and affected products as relevant content patterns; they do not establish keyword volume or ranking opportunity.

## Findings and changes

| Priority | Evidence | Implemented fix | Expected benefit |
| --- | --- | --- | --- |
| High | Sitemap assigns request time to unchanged methodology/legal pages. | Omit dates without recorded updates; use persisted publication/enrichment dates for incident content. | Credible crawl-change signals. |
| High | Homepage title repeats the topic over 80 characters; actual archive/detail titles differ from social metadata. | Emit one title from shared metadata. Start the homepage title with `AI Security Incident Monitoring` followed by the brand. Retain CVE/GHSA identifiers when shortening detail titles. | Clear search intent and consistent titles. |
| Medium | Detail descriptions allow 260 characters; archive descriptions repeat. | Cap detail descriptions at 160; include archive page number and published count. | Concise page-specific summaries. |
| Medium | Page 1 also resolves with `?page=1`; trailing slashes vary. | Permanent canonical redirects preserving attribution, safe page-number bounds, nonindexable 404s for invalid values. | Fewer duplicate entry URLs. |
| Medium | dateModified always equals publication. | Use recorded enrichment dates and display page updates. | Accurate modification signals. |
| Medium | Article schema lacks citations/publisher and structured breadcrumbs. | Real source citations, actual publisher, language, and BreadcrumbList matching visible navigation. | Better context and navigation. |
| Medium | ItemList positions restart on page 2. | Archive-wide positions, page-specific H1s and self canonicals. | Consistent collection semantics. |
| Medium | Temporary D1 failure can fail public crawler requests. | Optional public cache with bounded fallback. | Resilient availability. |
| Low | Large-image Twitter card has no representative image. | Use summary card. | Accurate social metadata. |
| Low | Error/API responses lack consistent index controls. | X-Robots-Tag and no-store for private/error responses; keep all published incidents indexable. | Clear non-content exclusion. |

## Validation

Tests verify exactly one title, social consistency, advisory identifiers, description length, unique archive descriptions, global list positions, breadcrumbs, citations, sitemap stability across clock changes, modification timestamps, redirects, and real nonindexable 404s. Cache tests cover freshness, bounded stale fallback, private exclusions, failures, and missing content.

Built Worker checks in Cloudflare's local runtime cover homepage, archive, seeded detail, robots, sitemap, redirects, cache hits, and private health. JSON-LD is parsed and compared with visible content. Google Rich Results Test, Search Console submission, mobile browser audit, and field Core Web Vitals measurements were not performed; local tests do not establish those results.

## Follow-up after rollout

Deployed on 2026-10-20 at 14:34 UTC. Live checks confirm the new homepage/archive titles, old incident detail and its citations/breadcrumbs, deep pagination, canonical redirects, and a 615-URL sitemap without fabricated static-page dates.

1. Verify live sitemap, titles, canonicals, schema, and old detail URLs.
2. Refresh the sitemap in Search Console and sample URLs in URL Inspection/Rich Results Test. Record actual index coverage and enhancement warnings.
3. Track impressions, clicks, CTR, and indexed incident pages over 28 days. Compare affected-product and vulnerability groups before adding landing pages.
4. Improve affected-version and mitigation detail using authoritative sources. Source availability/publication must remain independent of generated enrichment.
5. Add a sitemap index before reaching the existing 45,000-incident budget. Archive/detail access has no 200-record cutoff.
